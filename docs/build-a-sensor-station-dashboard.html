Chapter 13 Build a Sensor Station Dashboard

You can use an AI coding agent (Claude, ChatGPT, Copilot, or any other) to generate a complete sensor station dashboard for your project. This chapter gives you the prompt to paste, what to tell the AI, and how to launch the result.

No coding experience needed. You give an AI agent the prompt below, along with your project name. It creates three files. You run one command and open a browser.

13.1 What You Need

  1. An API token from CTT (see Chapter 1 — Request an API token)
  2. Your CTT account username and password (the same login you use at account.celltracktech.com)
  3. Your project name exactly as it appears on the CTT platform
  4. Python installed on your computer (python.org/downloads — check “Add Python to PATH” during install)
  5. An AI coding agent — any of these work:
    • Claude (free or Pro)
    • ChatGPT (free or Plus)
    • GitHub Copilot
    • Any other AI that can generate code

13.2 Step 1: Copy the Prompt Below and Give It to Your AI Agent

Open your AI agent and paste the following prompt. Replace only YOUR_PROJECT_NAME with your actual project name before sending.

⚠ Do NOT paste your API token, password, or username into the AI chat. The AI does not need your real credentials to generate the code. It only needs your project name. You will enter your credentials locally in Step 2, in a file that stays on your computer and is never sent to anyone.

Why: AI providers store conversations on their servers. Your credentials could be logged, reviewed by employees, used in training data, or exposed in a data breach. Keep them local.

Tip: You can also ask the AI to customize the dashboard further — add new panels, change colors, add station filtering, etc. The prompt gives it everything it needs to know about the CTT API.

13.2.1 The Prompt

Copy everything inside the box below:

I need you to create a sensor station dashboard for my wildlife tracking project.
My project name is: YOUR_PROJECT_NAME

Create three files that I place in a folder and run:

1. config.json — stores my credentials (I will fill in the real values)
2. proxy.py — a Python HTTP server that proxies browser requests to the CTT API
3. dashboard.html — a single-page dashboard I open in my browser

Here is everything you need to know about the CTT API:

== CTT API SPECIFICATION ==

BASE URL: https://api.internetofwildlife.com
All endpoints use POST with JSON body. Every request must include "token" in the body.
Timeout: 60 seconds.

ENDPOINT 1 — List Projects
POST /station/api/projects
Body: {"token": "..."}
Response: {"projects": [{"id": 73, "name": "Meadows V2"}, ...]}
Note: project "id" is an INTEGER.

ENDPOINT 2 — List Stations
POST /station/api/stations/
Body: {"token": "...", "project-id": 73}
Response: {"stations": [{"station": {"id": "6CA25D375881"}, "deploy-at": "2024-01-15T00:00:00.000Z", "end-at": null}]}
CRITICAL: "project-id" MUST be an integer, not a string. If you send "73" instead of 73 it returns empty.
Active stations have "end-at": null.

ENDPOINT 3 — List Station Files
POST /station/api/file-list
Body: {"token": "...", "station-id": "6CA25D375881", "begin": "2024-01-01"}
Optional: "end" (date, defaults to today), "file-types" (array), "limit", "offset"
Valid file-types: "data", "node-data", "gps", "log", "telemetry", "sensorgnome", "ble", "blu"
Response: {"files": {"data": [{"id": 123, "name": "CTT-...-raw-data.csv.gz", "file_at": "..."}], "node-data": [...], "gps": [...], ...}}
CRITICAL: "files" is a DICT keyed by file type, not a flat array. Each value is an array of file objects.

ENDPOINT 4 — Download File
POST /station/api/download-file/
Body: {"token": "...", "file-id": "..."}
Response: raw CSV text

ENDPOINT 5 — Station Checkins (DIFFERENT HOST AND AUTH)
GET https://account.celltracktech.com/station/station-data/{station_id}/
Auth: session cookie (NOT the API token). Requires CSRF login flow:
  Step 1: GET /accounts/login/ — extract csrftoken from Set-Cookie header
  Step 2: POST /accounts/login/ with csrfmiddlewaretoken, username, password
          Must include Referer header. Expect HTTP 302 redirect.
  Step 3: GET /station/station-data/{station_id}/ with session cookies
Returns up to 500 most recent checkins, newest first.
Response: {"checkins": [{"station": {"id": "..."}, "project": "...", "alias": "...",
  "received_at": "2024-05-18T12:00:04.512000+00:00", "lat": 40.0, "lng": -75.0,
  "bootcount": 3, "uptime": 12345, "cpu": 8, "free_memory": 900000,
  "available_space": 25000000, "beeps_since_last_checkin": 19,
  "unique_tags_since_last_checkin": 2, "modem": {"signal": -71, "carrier": "VZW"}}]}
If session expired: returns HTML instead of JSON (check Content-Type).

== PROXY ARCHITECTURE ==

The proxy runs on localhost (e.g. port 5000) using only Python standard library (no pip installs).
It serves dashboard.html and config.json as static files.
It maps browser requests to the real API:
  POST /api/projects       → POST https://api.internetofwildlife.com/station/api/projects
  POST /api/stations       → POST https://api.internetofwildlife.com/station/api/stations/
  POST /api/file-list      → POST https://api.internetofwildlife.com/station/api/file-list
  POST /api/download-file  → POST https://api.internetofwildlife.com/station/api/download-file/
  GET  /api/checkins/{id}  → GET  https://account.celltracktech.com/station/station-data/{id}/

The proxy must:
- Read credentials from config.json
- Inject the API token into every POST body automatically
- Coerce "project-id", "station-id", "file-id" to integers (the API rejects string IDs)
- Handle the CSRF login flow for checkins (login once, cache the session cookies)
- Re-login if the session expires (HTML response instead of JSON)
- Use only Python standard library (http.server, urllib, json, ssl)

== CONFIG.JSON ==

{
  "api_token": "PASTE_YOUR_API_TOKEN_HERE",
  "ctt_username": "PASTE_YOUR_CTT_USERNAME_HERE",
  "ctt_password": "PASTE_YOUR_CTT_PASSWORD_HERE",
  "project_name": "YOUR_PROJECT_NAME"
}

== DASHBOARD FEATURES ==

The dashboard.html should be a single self-contained HTML file (no build step) that includes:

1. Status cards — active station count, last checkin time, beep count, unique tag count
2. Interactive map — station GPS positions using Leaflet.js (CDN), with popup showing signal, beeps, tags, uptime, disk
3. Station health table — one row per station: station ID, last checkin, signal (dBm), CPU, disk (MB), beeps, tags
4. Time-series charts — tabbed: beeps over time, unique tags over time, signal strength over time (use Chart.js from CDN with chartjs-adapter-date-fns)
5. File inventory — table showing file count per type (last 30 days) with a donut chart breakdown
   File type labels: data="Raw (434 MHz)", node-data="Node Health", gps="GPS", log="Log",
   telemetry="Telemetry", sensorgnome="SensorGnome (166 MHz)", ble="BLE / Blu (2.4 GHz)"

The dashboard reads config.json at load to get the project name for the title.
API calls go through the local proxy (fetch('/api/projects'), etc.).
The workflow: load config → find project by name → get stations → get checkins per active station → get file list per station → render everything.

== KNOWN GOTCHAS ==

1. Project IDs must be integers in the JSON body — the API silently returns empty results for string IDs
2. The file-list response is a dict keyed by type, not a flat array
3. The checkins endpoint uses a completely different host and auth mechanism (session cookie, not API token)
4. If the checkin endpoint returns HTML (Content-Type: text/html), the session has expired — re-login
5. The CSRF login requires both the csrftoken cookie AND the csrfmiddlewaretoken form field, plus a Referer header
6. Station IDs can be alphanumeric (e.g. "6CA25D375881") — only project-id needs integer coercion
7. modem.signal can be null — handle this in charts and display

Please generate all three files complete and ready to use.

13.3 Step 2: Save the Three Files

The AI will give you three files. Create a new folder on your computer (name it anything, e.g. my-dashboard) and save them inside:

my-dashboard/
├── config.json
├── proxy.py
└── dashboard.html

Open config.json in a text editor and fill in your real credentials. This is the only place your credentials go — this file stays on your computer and is never sent to the AI or anyone else.

{
  "api_token": "paste_your_real_token_here",
  "ctt_username": "your_real_username",
  "ctt_password": "your_real_password",
  "project_name": "Your Project Name"
}

Do not commit this file to GitHub or share it with anyone.

Security note: This file contains your password. Do not share it, email it, or upload it anywhere. It stays on your computer only.

13.4 Step 3: Launch the Dashboard

Open your terminal (Mac/Linux) or Command Prompt (Windows), navigate to your folder, and start the proxy:

Mac/Linux:

cd my-dashboard
python3 proxy.py

Windows:

cd my-dashboard
python proxy.py

You should see something like:

Dashboard proxy running at http://localhost:5000
Project: Your Project Name
Press Ctrl+C to stop.

Open your web browser and go to http://localhost:5000/dashboard.html.

Your dashboard will load within a few seconds. To stop it, press Ctrl+C in the terminal.

The best part about using an AI agent is that you can ask it to modify the dashboard after the initial generation. Here are some example follow-up prompts you can give your AI:

13.5.1 Change the look and feel

“Change the header color to dark blue and add our organization’s name to the title”

13.5.2 Add new panels

“Add a panel that shows disk space remaining as a percentage for each station”

“Add a panel that shows how long each station has been online (uptime in days)”

13.5.3 Add filtering

“Add a dropdown at the top so I can filter everything by a single station”

“Add a date range picker that controls which checkin data is shown in the charts”

13.5.4 Add alerts

“Highlight stations in red in the health table if they haven’t checked in for more than 24 hours”

“Show a warning banner if any station’s disk space drops below 1 GB”

13.5.5 Change the charts

“Change the beeps chart to a bar chart grouped by day instead of a line chart”

“Add a chart that shows CPU load over time”

13.5.6 Add data export

“Add a button that downloads the health table as a CSV file”

When asking for changes, just tell the AI what you want in plain English. If it needs context about the API, point it back to the API spec in the prompt above or to Chapter 11 — API Reference.

13.6 Troubleshooting

13.6.1 “Project not found”

Your project name in config.json must match exactly — including capitalization and spaces. For example, "Meadows V2" is different from "meadows v2".

13.6.2 “Login failed” or no checkin data

Double-check your ctt_username and ctt_password in config.json. These are the same credentials you use to log in at account.celltracktech.com.

13.6.3 “Connection refused” in the browser

Make sure the proxy is still running in your terminal. If you closed the terminal, the proxy stopped.

13.6.4 “python3 is not recognized” (Windows)

Try python proxy.py instead. If that also fails, Python is not installed — download it from python.org and make sure to check “Add Python to PATH” during installation.

13.6.5 The AI generated code that doesn’t work

Tell the AI what went wrong. Copy the error message from your terminal or browser console and paste it into the chat. Common issues the AI might get wrong:

  • Sending project-id as a string — tell it: “The CTT API requires project-id to be an integer, not a string. The proxy must coerce it with int().”
  • Treating the file-list response as an array — tell it: “The /station/api/file-list response has files as a dict keyed by type, not a flat array.”
  • Not handling the CSRF login for checkins — tell it: “The checkins endpoint at account.celltracktech.com requires a CSRF cookie login, not the API token.”

13.6.6 Changing your project

Edit config.json, change the project_name, and refresh the browser page. No other changes needed.
